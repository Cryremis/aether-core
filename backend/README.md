# backend/README.md

AetherCore 后端服务。

## Skill 详情与市场发布者

`GET /api/v1/agent/skills/preview` 根据已授权会话、Skill 名称和来源读取文件清单与 `SKILL.md`。市场使用 `GET /api/v1/extensions/{entry_id}/preview`，可用 `version` 选择已发布版本。两个接口都可以通过 `file_path` 请求单个包内文本文件。市场安装接口接受可选 `version`，省略时使用当前版本。

后端启动时自动迁移市场条目。嵌入式发布者使用可空的本地用户 ID 和平台外部用户 ID，市场从宿主绑定同步的资料中显示姓名和账号。存量条目可从同平台、同用户的历史会话回填姓名，缺少账号时由后续宿主绑定补齐。历史发布审计保留原记录，新记录保存发布时的展示资料。升级时前后端一起发布。回退应用版本时可保留新增表和列，旧市场页面会恢复旧的发布者显示方式。

## 本地启动

1. 配置 `backend/.env`
2. 安装依赖
3. 构建沙箱镜像：

```bash
docker build -t aethercore-sandbox:latest -f docker/sandbox/Dockerfile .
```

4. 启动后端：

```bash
python -m uvicorn app.main:app --loop asyncio --host 127.0.0.1 --port 8100
```

## 沙箱要求

- 默认执行器为 `docker`
- 默认 `fail-closed`
- 沙箱不可用时拒绝执行，不允许自动回退到宿主机
- 会话 runtime 默认保留工作区与 `home/cache` 目录，容器重建后文件与 pip 用户安装缓存仍可复用
- 容器命令默认以 `sandbox` 用户在 `/workspace/work` 下执行；`/workspace` 及其常用子目录应保持可写

## 会话审计查询与性能

平台详情的审计页与管理控制台共用分页审计浏览器。

- 会话列表使用紧凑行，默认每页 50 条，可选择 25 / 50 / 100 条。
- 搜索覆盖标题、用户名、用户 ID、Session ID、Conversation ID 和宿主会话键，不搜索消息正文。
- 支持按最后消息时间、创建时间、更新时间、消息数量升序或降序排列；同值按 Session ID 稳定排序。
- 时间范围可选择最后消息时间、创建时间或更新时间。页面日期使用浏览器本地时区，包含结束当天，点击“搜索 / 应用”提交。
- 选择会话后默认显示最近 30 条展示消息，可翻到更早、更新的消息或回到最新。工具结果和压缩审计事件保留原有展示规则。
- “刷新列表”只刷新当前查询结果；“刷新消息”只刷新已选择会话的当前消息窗口。
- 详情读取持久化审计索引，不激活运行态、不创建工作区、不更新访问时间、不回写会话快照；缺失历史返回 404。未提交的流式 token 不进入审计消息，已落库的中断响应仍按原有恢复规则展示。

### API 兼容性

`GET /api/v1/admin/conversations` 新增以下可选参数：

| 参数 | 含义 |
| --- | --- |
| `limit` | 1–100；传入后 `data` 为 `{items, total, limit, offset}`，不传仍返回原有数组 |
| `offset` | 从 0 开始的分页偏移 |
| `q` | 最多 200 字符的元数据关键词；`%`、`_` 按字面搜索 |
| `sort_by` | `last_message_at`（默认）、`created_at`、`updated_at`、`message_count` |
| `sort_order` | `desc`（默认）或 `asc` |
| `time_field` | `last_message_at`（默认）、`created_at`、`updated_at` |
| `time_from` / `time_to` | ISO 时间，前闭后开；无时区按 UTC 解释 |

`GET /api/v1/admin/conversations/{session_id}` 新增可选的 `limit`（1–100）和 `before`（展示消息结束位置，不包含该位置）。传入 `limit` 时返回轻量详情：`transcript` 为当前窗口，`messages` 为空，`transcript_page` 为 `{total, start, end, has_more}`；省略 `before` 获取最新窗口。窗口位置针对当次完整展示历史计算，会话被编辑、重跑或压缩时应回到最新重新查看。

不传 `limit` 的详情调用仍保留原有完整返回格式。权限继续按当前管理员可管理的平台限制。此改动不影响宿主接口、端口、环境变量或沙箱行为。新增活动时间索引在后端启动时自动创建；审计派生表在首次写入或读取历史时自动创建。回滚代码时索引和派生表可保留，无需修改会话快照或归档格式；再次升级会校验来源版本并补建过期索引。前后端应一起发布，旧后端不支持新版分页响应。

### 验证与限制

回归覆盖 650 个会话的全局排序和分页、名称关联查询、关键词与时区边界、平台越权、305 条消息的有界读取、冷会话只读读取、压缩历史一致性、快速切换会话的过期响应和刷新失败重试。

列表仅查询元数据，不加载会话消息。详情的持久化索引由 `audit_transcript_sources`、`audit_transcript_heads`、`audit_transcript_items` 和 `audit_attempt_versions` 四张可重建表组成。单页按 `(session_id, position)` 联合主键读取，热路径不读取完整快照、不展开历史，只解码当前页消息与一份小元数据，进程重启后也能复用。

来源指纹在现有持久化过程中复用消息摘要与归档版本计算。普通访问时间、宿主名称和网络配置更新不重建消息索引；消息、归档版本、压缩审计记录、展示规则版本或可恢复响应发生变化时才失效。活跃运行的 token 更新不使已提交消息索引失效，运行结束后的可恢复响应版本会触发更新。读取未提交响应版本使用部分索引，避免扫描大量已提交尝试。派生消息沿用历史加密设置，会话历史删除时一并清理。

旧会话首次访问或消息来源发生变化后，首次读取会展开当前分支并原子重建一次；后续打开、刷新和任意翻页均直接读取索引。并发构建在发布前再次校验来源，避免旧结果覆盖新历史。只有旧 JSON、尚无账本的会话使用文件时间与大小校验变更，读取不会自动创建账本。

归档消息版本查询补充 `(session_id, message_id, seq DESC)` 联合索引，避免首次展开时反复扫描会话的全部归档。该数据库索引首次升级时需创建一次。2026-11-02 本地服务层样本（600 条消息、其中 500 条归档、含 1 个压缩事件）：首次创建审计索引约 126ms；100 次最新页读取中位数约 5.5ms、P95 约 8ms；100 次历史翻页中位数约 6.5ms、P95 约 10.4ms。不含网络和浏览器渲染耗时，生产延迟仍需结合部署环境验收。
