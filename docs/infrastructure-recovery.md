# 基础设施故障恢复

运行时保持原 HTTP/SSE、事件序号、错误分类和用户提示。无需数据库迁移、VACUUM 或新增配置。

## PTY 生命周期

原始 master fd 只在尚未交给文件对象时由创建函数关闭。`fdopen` 成功后移交所有权；`connect_read_pipe` 成功后由保存的 transport 关闭。正常退出、异常、取消、超时共用幂等清理，不再按旧数字 fd 二次关闭。管道绑定失败会回收已经启动的子进程。

## SQLite

- 连接按线程复用，保留 `check_same_thread=True`，每条连接显式设置 `busy_timeout=5000`。进程或数据库路径变化时弃用旧连接。嵌套读取使用独立的短生命周期连接，不提交外层事务。线程退出时释放连接。
- `retry_sqlite` 只包围数据库操作。首次失败后最多重试三次，退避 0.2 / 0.5 / 1 秒，每次增加 0–20ms 随机量。事务和锁释放后才退避；嵌套操作的重试延迟到外层回滚后。
- 仅重试 BUSY 类及明确列举的 IOERR 子码。没有错误码的异常仅对精确的 `disk I/O error`、`database is locked`、`database is busy` 文案回退。损坏、约束、语法、只读等错误原样抛出。
- 异常时回滚；SQLite 错误后的连接直接丢弃。无法确认回滚、已部分提交的多步操作、没有结果核对机制的未知提交结果均停止重放，避免用重试掩盖数据一致性问题。含文件安装或工具副作用的方法不能套此装饰器。
- run 事件仍先提交数据库再发布。已确认回滚时重新读取游标；提交结果不确定时保留原 seq、时间和内容，重新读取原事件核对。核对成功视为本次写入成功，不追加新事件。冲突则拒绝覆盖。
- 会话账本以已有快照 digest 核对重复提交。工具执行的副作用不在数据库重试范围内；不能确认 claim 的提交结果时不会自动重跑工具。

每次数据库失败仅记录操作名、尝试次数、失败阶段、`sqlite_errorcode`、`sqlite_errorname` 和是否重试，不记录 SQL 参数、消息或工具结果。最终仍失败时沿原运行失败路径处理。

退避总量最多约 1.76 秒，不含 SQL 执行、I/O 和 SQLite 等锁时间。保留 5 秒 busy timeout 就不能同时保证整个操作两秒内结束；本实现不增加该超时，也不在退避时持有事务锁。`durable_io.finish_on_cancel` 保持不变，取消调用方仍等待已开始的提交和发布完成。

## 模型传输

递归检查异常组的所有叶子，只有全部属于传输错误、已有可恢复模型流错误或精确匹配的 fd transport RuntimeError 才重试。取消继续取消，混有程序错误的组不重试。

复用既有 stream_retry 次数和时间窗口。已有正文按 attempt 保留后续写，未完整生成的工具参数不执行，已完成工具回执继续回放。收到完整模型终态后，HTTP 清理阶段的可恢复传输错误不触发重放。耗尽后的分类和文案维持原逻辑。

## 验证

`backend/tests/test_infrastructure_recovery.py` 覆盖执行/提交前/提交后故障、扩展错误码、并发写入与故障、部分提交拒绝重放、嵌套事务、异常组恢复与耗尽、取消等待提交、fd 复用，以及 Linux 真实 PTY 创建、退出和取消。故障注入只能证明恢复逻辑，不能证明生产环境 IOERR 的底层原因已经全部排除；上线后仍需按扩展码观察。
